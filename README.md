# てのひらアトリエ

Webカメラと手の動きで立体を組み合わせる、3D創作ワークショップです。
Editorで編集した作品を、WebSocketで別ブラウザ・別端末のViewerにも反映します。

## 起動

Node.jsのバージョンは [mise](https://mise.jdx.dev/) で `mise.toml` に固定しています。

```sh
mise install
npm ci
npm run dev
```

miseを使わない場合は、`mise.toml` と同じバージョンのNode.js（22.15以上が必須）を用意してください。

表示された `http://127.0.0.1:5173` をブラウザで開きます。
初回起動時にGoogle公式のHand Landmarkerモデル（約8 MB）を取得します。
WASMとモデルは `public/` に配置され、以後はローカルから読み込みます。
モデル取得後は、開発・ビルド・ハンドトラッキングに外部CDNへのアクセスは不要です。
カメラ映像とランドマークはサーバーへ送信しません。

## EditorとViewerの同期

- Editor: `http://127.0.0.1:5173/`
- Viewer: `http://127.0.0.1:5173/?mode=viewer`

同じサーバーにつなぐと、立体の追加・削除・色・位置・大きさ・回転がリアルタイムに共有されます。
ドラッグやスライダーの操作中も約50ms間隔で送信します。Viewerはカメラ入力なしで自動周回を続けます。
接続が切れた場合は自動で再接続し、最新の作品を取得します。接続待ち・再接続中はviewportに表示します。
Viewerを先に開いた場合は、最初のEditorが接続するまで待ちます。

作品を分ける場合は、両方のURLに同じ `room` を指定します。
例: `/?room=workshop` と `/?room=workshop&mode=viewer`（英数字・`_`・`-`、1〜64文字）。
別端末からは `npm run dev -- --host 0.0.0.0` で起動し、URLのホストをサーバーのIPに置き換えてください。
EditorでWebカメラを使う場合はHTTPSが必要です（localhostは例外）。

サーバーはシーンをメモリ上に保持します。サーバー再起動後は、最初のEditorのブラウザに保存された作品で初期化します。
接続先に作品がある場合はサーバー側を優先します。同じ立体への同時編集は最後に届いた変更を採用し、立体ごとのロックは未実装です。

## 操作

- viewport上部の「Viewer」で表示専用モードに切り替えます。Webカメラは停止し、作業エリア中央の固定点を見ながら約2分で一周します。中央からの距離は24で固定し、立体の追加・移動・サイズ変更や画面サイズの変化によって視点を寄せたり引いたりしません。「Editorに戻る」またはEscapeで編集画面へ戻ります。
- `/?mode=viewer` で直接Viewerを開くこともできます。同じRoomのEditorの作品を受信して表示します。
- 創作ツールはすべてviewport内にあります。下の「追加」「色」「編集」「視点・左右」から開きます。マウス・タッチでも同じメニューを使えます。
- 「追加」でCube / Sphere / Cylinder / Cone / Torusを選び、「○○を追加」で確定します。形の選択だけでは立体を追加せず、選択中の立体の形も変更しません。追加後はメニューを閉じます。
- 「カメラを開始」を押し、カメラ使用を許可します。
- 初期設定は **左手で視点、右手で立体とメニュー** を操作します。両手を認識でき、片手ずつ映しても使えます。
- 青のカーソルをメニューやボタンに合わせ、親指と人差し指をつまむと決定します。つまみ続けても連打にはなりません。次の操作の前に指を開いてください。メニュー内では背後の立体を掴みません。
- 「色」では選択中の立体と次に追加する立体の色を変更します。「選択を解除」で次に追加する立体だけの色を選べます。
- 「編集」では大きさ・奥行き・回転のバーをつまんで左右に動かします。指を開く、手が見えなくなる、視点操作に切り替わると確定して自動保存します。複製・削除も手で操作できます。
- 視点用の手で親指と人差し指をつまみ、そのまま動かすと視点が回転します。指を開く、または手を画面外に出すと止まります。
- 「視点・左右」で回転・平行移動・ズームを選べます。ズームはつまんだまま上に動かすと拡大、下に動かすと縮小します。
- 「視点・左右」の「左右を入れ替える」で **右手で視点、左手で立体とメニュー** に切り替えられます。もう一度押すと戻ります。設定は同じブラウザに保存します。
- 切り替え、視点操作モードの変更、「視点を戻す」、Escape、ウィンドウからフォーカスが外れた後は、指を一度開いてからつまむと操作を再開できます。
- 立体用の手の親指と人差し指の中点に、青のカーソルが表示されます。立体に合わせてつまむと選択して掴めます。そのまま動かし、指を開くと離します。カーソルを重ねるだけでは選択を変更しません。視点用の手のカーソルはオレンジです。
- 両手で同時につまんだ場合は視点操作を優先し、掴んだ立体を離します。立体を再び掴むには、立体用の手の指を開いてからつまみ直してください。マウスで立体をドラッグしている間は手で視点を動かしません。
- 手が見えなくなる、タブを離れる、カメラを止める場合にも掴んだ立体を離します。
- カメラなしでも、立体を左ドラッグ（タッチでは1本指）して移動できます。
- 右ドラッグで視点を回転、スクロールでズーム。「視点を戻す」で初期視点に戻します。
- 選択した立体の色・大きさ・奥行き・横回転をUIで変更できます。「縦に45°回転」は45°ずつ回します。
- 削除、複製に対応。`Delete` / `Backspace`で選択中の立体を削除し、`Escape`で選択とメニューを解除できます。
- 移動はカメラに平行な平面上で行い、細かな奥行き調整はスライダーを使用します。
- 最大100個。ドラッグ／スライダー操作は終了時に自動保存します。

作品は同じブラウザのlocalStorageに自動保存します。「作品を保存／開く」でJSONファイルとして持ち運べます。
自動保存の控えはブラウザ・ポート・Roomごとです。接続中の作品はWebSocketで共有します。
作品保存は試作確認用の補助機能です。Galleryは未実装です。

## 検証・ビルド

```sh
npm run check
npm test
npm run test:http
npm run test:sync
npm run build
npm start
```

`npm start` は `http://127.0.0.1:3000` で `dist/` とWebSocketを配信します。
先に `npm run build` を実行してください。本番サーバーは `dist-server/index.mjs` にビルドされ、起動時のTypeScript変換を省きます。
モデルとWASMも含まれます。`HOST=0.0.0.0 PORT=3000 npm start` で他端末から接続できます。
`npm run dev` と `npm run preview` にもWebSocketサーバーが組み込まれています。
静的ファイルだけのホスティングでは同期できません。HTTPSのリバースプロキシ経由で配信する場合は `/sync` のWebSocket Upgradeも転送してください。
通常の配信ではHTTPSが必要です（localhostはHTTPでもカメラ利用可）。
展示PCではChrome / Edgeの現行版、WebGL、カメラ権限を確認してください。
推論はCPUを使うWeb Workerで最大20fpsに抑え、描画と分離しています。

`npm test` では保存データの検証のほか、左右の割り当て、認識順序の変化、独立したピンチ判定、
視点操作の開始・停止、左右切り替え後の誤操作防止を検証します。
`npm run test:http` は同時ファイル配信、ETagによる再取得の省略、ファイル更新時のキャッシュ無効化、ダウンロード中断を検証します。
`npm run test:sync` は実際のWebSocketで、Editor→Viewerの変更配信、後からの参加、再接続、Room分離、Viewerの書き込み拒否を検証します。
開発サーバーの `/tests/hand-worker.html` でモデルの動作をカメラなしで再検証できます。
実際のWebカメラでの左右の認識・操作感、展示PC上の両手推論の性能は引き続き確認が必要です。
実機では左手だけで視点操作、右手だけで立体移動、両手操作の優先順位、左右の入れ替えと
リロード後の設定復元、手が隠れた場合の停止を確認してください。

## Docker / NeoShowcase

```sh
docker build -t tenohira-atelier .
docker run --rm --init -p 127.0.0.1:3000:3000 tenohira-atelier
```

Editorは `http://localhost:3000/`、Viewerは `http://localhost:3000/?mode=viewer` で開きます。
Dockerfileは `mise.toml` と同じNode.js 24.19.0を使用します。
依存関係の取得とモデルのダウンロードはビルド時に行うため、その際はインターネット接続が必要です。
起動時にはモデルの取得やフロントエンドのビルドを行いません。
実行イメージには本番依存関係・`dist/`・`dist-server/` を含め、`node` ユーザーで実行します。
モデルとWASMは64KiBのチャンクで配信し、同時接続数に比例してファイル全体をメモリに保持することを避けます。
ETagを使って変更のないファイルの再送を省き、WebSocketのシーン配信データは同じ内容を接続数分作り直さず共有します。

NeoShowcaseではRuntimeアプリとしてルートの `Dockerfile` を指定し、公開先ポートを `3000` に設定してください。
コンテナは標準で `HOST=0.0.0.0`、`PORT=3000` で起動し、HTTPとWebSocketを同じポートで受け付けます。
公開後はHTTPSでEditorのカメラ入力とViewerへの同期を確認してください。
作品は現状メモリ上にあり、コンテナ内の永続保存は行いません。

メモリの比較ではDockerを200,000,000バイトに制限し、20接続でモデル・WASMを同時取得しました。
変更前は上限付近に達して取得がタイムアウトしましたが、ストリーミング配信とサーバーの事前ビルド後は正常に完了しました。
100ms間隔で測定したNode.jsプロセスのピークRSSは約187MBから約99MBに減少しました。
続いて100個の立体を20接続で共有し、4接続からそれぞれ毎秒20回の編集を10秒間送信した際のピークRSSは約86MBでした。
これはローカルDockerでの測定値であり、NeoShowcaseのメトリクスと直接同じ値になることを保証するものではありません。

## 構成

- `src/main.ts`: 操作の接続、メニュー状態、自動保存、ファイル入出力
- `src/menu.ts`: viewport内の創作メニュー
- `src/hand-menu.ts`: 手のカーソルによるDOMの当たり判定、ボタン操作、スライダーのドラッグ
- `src/scene.ts`: Three.js表示、選択、ドラッグ、視点操作、Viewerの固定距離での自動周回
- `src/sync.ts`: WebSocket接続、変更送信、受信反映、自動再接続
- `server/sync.mjs`: Roomごとのシーン管理、検証、WebSocket配信
- `server/index.mjs`: HTTPのストリーミング配信、キャッシュ、WebSocketサーバーの起動
- `vite.server.config.mjs`: 本番サーバーとシーン検証コードのJavaScriptへのビルド
- `src/gesture.ts`: 左右の認識結果の取り込み、手の役割切り替え、ピンチ判定、平滑化、視点操作の移動量
- `src/hand.ts` / `src/hand.worker.ts`: カメラ、モデル準備、端末内推論、リソース解放
- `src/model.ts`: シーンデータ、保存データの検証
- `scripts/prepare-assets.mjs`: ローカルWASMと公式モデルの準備
